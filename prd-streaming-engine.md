# PRD: Live Streaming MVP — Engine-Optimized

## Problem Statement

The coder-harness engine produces zero visibility during execution. When it runs a 15-task PRD, operators cannot see which task is running, inference metrics, or GPU status. The engine outputs to stdout via `print()` only. We need a live streaming server with a browser dashboard.

## Solution

Build a self-contained Python streaming server (FastAPI + SSE) on port 3081 that accepts events from the engine pipeline and streams them to a browser dashboard via Server-Sent Events.

## User Stories

1. As a developer, I want to POST engine events (task start/complete, inference metrics, quality gate results) to a streaming server so they are captured and broadcast in real time.
2. As a developer, I want to view a live HTML dashboard in my browser showing task progress, inference speed (tok/s), GPU temperature, and quality gate scores.
3. As a developer, I want the dashboard to auto-reconnect via SSE Last-Event-ID when the connection drops, without losing events.
4. As a developer, I want the streaming server to store events in SQLite WAL so I can replay past sessions and run ad-hoc queries.
5. As a developer, I want the streaming client to be a simple Python class I can import and call from the engine pipeline with one line: `client.emit("task.start", {...})`.

## Implementation Decisions

### Runtime Environment

- Python 3.12, pip available
- Available libraries: `fastapi`, `uvicorn`, `sqlite3` (stdlib), `json` (stdlib), `datetime` (stdlib), `ulid-py` (for event IDs), `threading` (stdlib)
- Port 3081 on localhost (same host as engine, no SSH needed via transport.py)
- SQLite database: `streaming-events.db` in the project directory

### Module Organization

Create these files in the project root:

- `streaming_server.py` — FastAPI app: SSE endpoint, event ingest, ring buffer, SQLite persistence, dashboard HTML serving. This is the main server. ~250 lines.
- `streaming_client.py` — Lightweight Python client class for emitting events from the engine. Single class `StreamingClient` with `emit()` and `emit_batch()` methods. ~100 lines.
- `dashboard/index.html` — Self-contained HTML+CSS+JS dashboard. Dark theme, inline styles, EventSource for SSE, auto-reconnect, real-time task timeline, inference metrics panel, GPU status gauges, quality gate score bars. ~400 lines.

### Dependency Order

1. **T01** first: `streaming_client.py` — no dependencies, the client is self-contained.
2. **T02** second: `streaming_server.py` — depends on the event schema defined in T01 (same envelope format).
3. **T03** third: `dashboard/index.html` — depends on the SSE endpoint from T02 being available.

### Event Envelope Schema

Every event must conform to this JSON schema:

```json
{
  "id": "01HX7K2M...",          // ULID string (auto-generated by server if omitted)
  "seq": 42,                     // Monotonic sequence (auto-assigned by server)
  "time": 1735689600000,         // Server wall-clock, Unix epoch ms (auto-assigned)
  "source_time": 1735689599500,  // Producer's local timestamp
  "source": "engine",            // "engine" | "dsh" | "system"
  "type": "task.start",          // Namespaced event type
  "data": {}                     // Event-specific payload
}
```

### Event Types

| Type | Data Fields | Description |
|------|-------------|-------------|
| `pipeline.start` | `prd_title`, `total_tasks` | Pipeline begins |
| `pipeline.complete` | `total`, `completed`, `failed`, `duration_s` | Pipeline finishes |
| `task.start` | `task_id`, `title` | Task begins |
| `task.complete` | `task_id`, `duration_s` | Task finishes |
| `task.fail` | `task_id`, `error` | Task failed |
| `inference.start` | `task_id`, `port`, `model` | BeeLlama API call begins |
| `inference.complete` | `task_id`, `tok_s`, `prompt_ms`, `gen_ms`, `tokens` | API call done |
| `quality.result` | `task_id`, `overall`, `details` | Quality gate result |
| `test.result` | `task_id`, `passed`, `failed`, `total` | Test result |
| `git.commit` | `task_id`, `sha`, `message` | Code committed |
| `gpu.snapshot` | `gpu_index`, `temp_c`, `vram_used_mb`, `vram_total_mb`, `util_pct` | GPU state |
| `system.heartbeat` | `viewers` | Periodic liveness (every 30s) |

### SQLite Schema

```sql
CREATE TABLE IF NOT EXISTS live_events (
    id TEXT PRIMARY KEY,
    seq INTEGER NOT NULL UNIQUE,
    time INTEGER NOT NULL,
    source TEXT NOT NULL DEFAULT 'engine',
    type TEXT NOT NULL,
    data TEXT NOT NULL DEFAULT '{}',
    created_at TEXT DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_live_events_type ON live_events(type);
CREATE INDEX IF NOT EXISTS idx_live_events_seq ON live_events(seq);
```

### API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/events` | Ingest a single event. Body: JSON event envelope. Returns 201 with assigned `id`, `seq`, `time`. |
| `POST` | `/events/batch` | Ingest multiple events. Body: JSON array. Returns 201. |
| `GET` | `/stream` | SSE stream. Query params: `since=<event-id>` for replay. Headers: `Last-Event-ID` also supported. |
| `GET` | `/` | Serves `dashboard/index.html` |
| `GET` | `/health` | Returns `{"status": "ok", "events": <count>}` |

### Ring Buffer

- In-memory ring buffer: 500 events
- On SSE reconnect with `Last-Event-ID` or `?since=<id>`: replay all events with seq > last_seq from the ring buffer
- If ring buffer doesn't go back far enough, fall back to SQLite query

## Testing

1. Start server: `python3 streaming_server.py --port 3081`
2. POST test event: `curl -X POST localhost:3081/events -H "Content-Type: application/json" -d '{"source":"engine","type":"test","data":{"msg":"hello"}}'`
3. View stream: open `http://localhost:3081/` in browser
4. Verify reconnection: refresh page, confirm events replay from buffer
5. Verify SQLite: `sqlite3 streaming-events.db "SELECT count(*) FROM live_events"`
