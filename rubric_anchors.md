# Scoring Rubric Anchors

## Correctness (Execution-Based)

| Score | Anchor |
|-------|--------|
| 0 | Code crashes on any input, or produces completely wrong output |
| 1 | Crashes on valid input, or returns wrong type |
| 2 | Works for trivially simple cases only (e.g., empty input) |
| 3 | Passes simple cases, fails edge cases or non-obvious inputs |
| 4 | Passes stated test cases but misses common edge cases |
| 5 | Passes most stated test cases and some edge cases |
| 6 | Passes all stated test cases, minor issues with edge cases |
| 7 | Passes all stated test cases and handles most edge cases |
| 8 | Passes all test cases including edge cases, correct output format |
| 9 | Passes all + handles edge cases + input validation + error states |
| 10 | Comprehensive test coverage demonstrated, no failures under any reasonable input |

## Completeness (Checklist-Based)

| Score | Anchor |
|-------|--------|
| 0 | Addresses none of the requirements |
| 1 | Mentions the problem but provides no solution |
| 2 | Partial solution, addresses 1-2 requirements |
| 3 | Addresses some requirements, misses 2+ explicitly stated ones |
| 4 | Addresses most requirements, misses 1-2 minor ones |
| 5 | Addresses all stated requirements |
| 6 | All requirements + basic error handling |
| 7 | All requirements + error handling + basic documentation |
| 8 | All requirements + error handling + documentation + type hints |
| 9 | All requirements + error handling + documentation + type hints + edge cases |
| 10 | Production-ready with extras (logging, monitoring, configuration) |

## Quality (Judge-Scored)

| Score | Anchor |
|-------|--------|
| 0 | No discernible code quality or incoherent output |
| 1 | Code is barely functional, no structure |
| 2 | Working code but no organization, naming is poor |
| 3 | Basic organization, some meaningful variable names |
| 4 | Reasonable structure, most names are descriptive |
| 5 | Clean code with logical organization, good naming |
| 6 | Well-organized with helper functions, consistent style |
| 7 | Clean abstractions, appropriate use of language features |
| 8 | Excellent design patterns, DRY, single responsibility |
| 9 | Idiomatic code, leverages language strengths, elegant solutions |
| 10 | exemplary quality — production-grade, exemplary patterns, zero technical debt |

## Intelligence (Judge-Scored)

| Score | Anchor |
|-------|--------|
| 0 | No evidence of understanding the problem |
| 1 | Minimal understanding, brute-force approach |
| 2 | Understands problem but uses naive approach |
| 3 | Basic understanding, conventional solution |
| 4 | Good understanding, standard best practices applied |
| 5 | Solid understanding, appropriate algorithm/data structure selection |
| 6 | Strong understanding, considers trade-offs |
| 7 | Sophisticated approach, anticipates future needs |
| 8 | Expert-level reasoning, optimal algorithm choice with justification |
| 9 | Novel insights, considers system-level implications, forward-thinking |
| 10 | Exceptional insight — demonstrates deep expertise, novel optimizations, or paradigm-shifting approach |

## Role-Fit: Orchestrator Tasks (Judge-Scored)

| Score | Anchor |
|-------|--------|
| 0 | No evidence of orchestrator thinking |
| 1 | Provides direct implementation instead of planning |
| 2 | Some planning but lacks structure or depth |
| 3 | Basic plan with some logical organization |
| 4 | Reasonable plan, covers main concerns |
| 5 | Good plan with clear phases and rationale |
| 6 | Structured plan with dependencies identified |
| 7 | Comprehensive plan with risk assessment and contingencies |
| 8 | Expert-level planning, considers team dynamics and business impact |
| 9 | Demonstrates leadership thinking, stakeholder management, and strategic trade-offs |
| 10 | Exceptional — shows seasoned engineering management judgment, anticipates organizational challenges |

## Role-Fit: Coder Tasks (Judge-Scored)

| Score | Anchor |
|-------|--------|
| 0 | No code or completely irrelevant output |
| 1 | Minimal code with no structure |
| 2 | Working code but not task-appropriate |
| 3 | Basic implementation meeting minimal expectations |
| 4 | Reasonable implementation, mostly appropriate style |
| 5 | Clean implementation appropriate for the task |
| 6 | Good implementation with attention to task constraints |
| 7 | Excellent implementation, exceeds basic requirements |
| 8 | Production-quality code with proper patterns |
| 9 | Outstanding implementation showing deep language and domain expertise |
| 10 | Exemplary — demonstrates mastery of language, patterns, and problem domain |

## Role-Fit: Multi-Turn Tasks (Judge-Scored)

| Score | Anchor |
|-------|--------|
| 0 | No coherent multi-turn progression |
| 1 | Repeats same response each turn |
| 2 | Some progression but loses context between turns |
| 3 | Maintains context, basic progression |
| 4 | Good context retention, reasonable evolution |
| 5 | Each turn builds meaningfully on the previous |
| 6 | Smooth progression with clear improvements per turn |
| 7 | Excellent iterative refinement, each turn adds clear value |
| 8 | Demonstrates understanding of design evolution, makes good trade-offs |
| 9 | Exceptional iteration — anticipates needs, clean architecture evolution |
| 10 | Masterful — each turn demonstrates deepening expertise and thoughtful design decisions |
