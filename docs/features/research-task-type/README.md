> Spec: `docs/features/research-task-type/EPIC.md`, `TICKETS.md`.
> Authoritative amendments: `.scratch/research-task-type/GRILL-S4.md`
> (7 deltas — mandatory verdict position, spans required, source-graph
> cycle check, primary-source ratio, claim density, answer-the-question,
> staged validator).

## What it does

A `research` task type: the atom produces a **cited verdict document**
(`verdict.md` with `[claim-N]`/`[src-N]` markers) plus a **deterministic
sidecar** (`verdict.evidence.json`, generated by post-processing the
markers, never by the LLM). The gate is two-layer per ADR-0004:

1. **Deterministic floor** — staged `EvidenceValidator` (stages 0-5,
   short-circuit between stages, report-all within stage):
   structure, citation format, claim coverage, source reachability,
   no self-support, **no cycles in either the claim→source graph or the
   source→source graph**, claim density ≥2/1000 tokens, contradictions
   carry resolutions, answer-the-question TF-IDF check. No LLM sets
   `passed`.
2. **LLM entailment scoring** — `EvidenceScorer` (judge model, 5
   dimensions: citation_coverage, claim_traceability,
   contradiction_handling, verdict_justification, source_quality),
   threshold **6.0**.

## Verdict contract

A valid verdict markdown document MUST contain these sections:

```
## Verdict
Position: supported|refuted|inconclusive
Confidence: <float 0.0-1.0>
<free-text answer to the research question>

## Sources
- [src-N] type: <type> uri: <uri> title: <title>

## Claims
- [claim-N] <claim text> [src-M]

## Contradictions
- between [N, M] resolution: <explanation>

## Citations
[claim:N, src:M, "<evidence span>", <confidence>]
```

**Anti-mush rules** (GRILL-S4 delta 1): `## Verdict` must state a
position (supported/refuted/inconclusive) AND a confidence. Hedged mush
= deterministic FAIL.

**Spans required** (GRILL-S4 delta 2): a citation without an evidence
span is decoration → deterministic FAIL.

**Markers**: `[claim-N]` / `[src-N]` / `[source-N]`. The LLM emits
markers only; `sidecar.py` parses them deterministically into
`verdict.evidence.json`.

## Registration hooks (T10)

- `engine/prd.py`: `CATEGORY_TO_TYPE["research"] = "research"` — PRDs with
  `category: research` parse to `task_type='research'`.
- `engine/__init__.py`: `task_role()` returns `"researcher"` for research
  tasks; `max_tokens_by_role["researcher"] = 8192`.
- `engine/pipeline.py`: `"evidence_check"` retry key in `task_retries`.
- `engine/prompts.py`: research branch in `build_prd_result()` sets
  `is_research` and `role` flags.
- `engine/cli.py`: `ace research` thin CLI — runs a single research atom
  from a PRD JSON file (mock-transport e2e).

## Oracle summary

| Layer | Mechanism | Threshold | Sets `passed`? |
|---|---|---|---|
| Deterministic floor | `EvidenceValidator` (stages 0-5) | all stages pass | Yes |
| LLM entailment | `EvidenceScorer` (judge model) | overall ≥ 6.0 | No (ADR-0004) |

On failure: one regeneration retry with failing `checks[]` as
`error_ctx` → judge-model escalation → T4 re-plan signature
`("evidence", check_name)`.
